# DOC-08 · Genetic & Genomic Report — Extraction & Verification Specification v1.0

**Status:** REVIEW (functional specification; no screens, no code) · **Date:** 2026-11-23 · **Category:** DOC-08 of the nine approved document types.
**Builds on (APPROVED):** Document Classification v1.0 (DOC-08: DNA testing, genetic testing, pharmacogenomics/PGx reports; "restricted-by-default sensitive storage; no independent genetic interpretation"); **CLR-08** ("apply restricted-by-default controls and do not automatically interpret genetic findings"; "explicit consent before expanded processing"; "prescriptions must not trigger genetic interpretation"); **QA-DOC-08** ("no autogenerated interpretation or actionable prescribing claim"); Verification & Recovery v1.0 (DOC-08 items: "permitted document metadata; restricted content handled under approved safeguards"; VER-AC-10.5; VER-E2E-13; VER-OD-09); Classification open item 9 (special consent and access, subject to privacy/legal review); locked S-RX-01–05, S-RX-03 v1.1–v1.6, A01 App lock; DOC-02–07 v1.0 patterns.
**Labels:** APPROVED · PROPOSED (needs your approval) · OPEN · **LEGAL GATE** (cannot ship before privacy/legal review).
**Approval boundary:** product behaviour only. This category is the most restricted in Ayoreni: its release is gated on privacy/legal review (DOC08-OD-08).

## 2. What is read, and what is not (PROPOSED; the safety core of this category)
**Ayoreni reads only permitted metadata** (APPROVED "permitted document metadata"). It does **not** extract, store as data, display as text, summarise or interpret any finding: no genes, variants, genotypes, PGx phenotypes ("poor metaboliser"), risk statements, carrier status, ancestry or prenatal results. These stay **only in the original document**, which the person opens themselves.

| ID | Permitted metadata | Tier |
|---|---|---|
| GEN-D01 | **Name on document** | Review-required (patient check) |
| GEN-D02 | **Report date** (and sample collection date if printed) | Review-required |
| GEN-D03 | **Laboratory / provider** as printed | Review-required |
| GEN-D04 | **Test name as printed** ("Hereditary Cancer Panel", "Pharmacogenomic Panel") | Review-required |
| GEN-D05 | Ordering doctor, if printed | Optional |
| GEN-D06 | Report / sample ID | Optional; used for duplicates; masked on screen |
| GEN-D07 | Report type as printed (final, amended, addendum) | Optional |

**Explicit consent before expanded processing (APPROVED CLR-08):** in this release there is **no** expanded processing. If a later release proposes reading findings, it needs its own spec, a separate consent screen and legal approval (DOC08-OD-07).

**AI processing limit (PROPOSED · LEGAL GATE):** after classification identifies a genetic report, the AI reader is limited to the metadata block (header/first page). Text from the findings pages is not kept in Ayoreni’s reading layer, logs or audit records (rule 8).

## 3. What must be checked (PROPOSED)
| Tier | Items |
|---|---|
| Required to save | Confirmed type and profile (APPROVED RX-VER-02) |
| Review-required for **Verified** | Name on document, report date, laboratory, test name |
| Optional | Ordering doctor, report ID, report type |
"Verified" here means the details are checked — never that any finding was checked (APPROVED VER-AC-01.6 principle).

## 4. Restricted by default (APPROVED principle; PROPOSED behaviour)
| Where | Behaviour |
|---|---|
| Records list | Row shows **"Restricted record"** with a lock icon and the date only; test name and lab hidden until unlocked |
| Opening the record or the original | Requires device authentication (app lock / Face ID / fingerprint, A01 pattern) every time, even if the app is already unlocked |
| Search | Not found by test name, lab or contents; only by "Restricted" filter after unlock (VER-AC-10.5) |
| Timeline | A neutral entry "Restricted record · 12 Oct 2026", only after unlock; otherwise not shown |
| Thumbnails, previews, recent files, app switcher | Never shown; app-switcher snapshot blurred when the record is open |
| Notifications | Never name the test, lab or category; verification reminders say "You have a record to finish checking" |
| Sharing, export, Emergency Health Card | **Excluded** by default; sharing one record needs an explicit per-share choice after unlock (DOC08-OD-04) |
| Caregivers / family access (future) | Excluded unless the person explicitly grants it for this record (DOC08-OD-05) |
| Pending Verification list | Shown as "Restricted record" with the status, no test name |

## 5. Medicines, conditions and other data (APPROVED CLR-08, QA-DOC-08)
- No warnings, labels, dose suggestions or "avoid" messages on any medicine from a genetic report — including PGx. No S-RX-04.
- Prescriptions, lab reports or notes that mention a gene or PGx result never trigger genetic interpretation and never link automatically to this record.
- No conditions, risks or family-history entries are created or suggested.
- No links to relatives’ profiles; a genetic report is never shared to or matched with another profile.
- Disclaimer: "This is your genetic report, kept restricted. Ayoreni doesn’t read or explain the results."

## 6. Interpretation boundary (APPROVED)
No explanation of what a result means, no risk wording, no "talk to a genetic counsellor about X" generated from findings. A fixed, non-personalised line is allowed: "If you have questions about this report, ask the doctor or counsellor who ordered it." (PROPOSED copy).

## 7. Downstream use
### 7.1 Records
Saved in Records as a restricted record (§4). The person can **Change Restriction** only for: hiding the test name from the list even after unlock (default: shown after unlock). Removing the restriction entirely is **not** offered in this release (DOC08-OD-03).

### 7.2 Changing the category
If the person changes DOC-08 to another category, the restriction **stays** until they confirm: "This record will no longer be restricted. Its contents may be read like other records." **Keep Restricted** (default) / **Remove Restriction**. Changing **to** DOC-08 applies the restriction immediately and removes any extracted content from the reading layer (PROPOSED).

### 7.3 Deletion
**Delete This Record** removes the record and the original from Ayoreni (subject to the retention policy under legal review); confirmation names what is removed. No soft-hidden copies remain visible (OPEN, LEGAL GATE).

## 8. Duplicates and versions (PROPOSED)
| Signal | Behaviour |
|---|---|
| Same file | S-RX-02 exact-copy sheet (shown only after unlock) |
| Same lab + report ID | Look-alike sheet |
| Amended report / addendum | **It’s an Updated Copy**: latest first, earlier kept and labelled; both restricted |

## 9. Privacy and legal (LEGAL GATE)
### 9.1 Storage
Same private storage and signed-URL rules as all documents (rules 5–6); the restricted flag is enforced server-side, not only in the app (PROPOSED).
### 9.2 Audit
Opening a restricted record is audit-logged with IDs, action code and time only (rule 8).
### 9.3 Prenatal reports (India)
Under India’s PCPNDT Act, disclosure of fetal sex is prohibited. Ayoreni never extracts, displays or infers fetal sex or any prenatal result; only metadata (§2) is read. Whether prenatal genetic reports may be stored at all is a legal decision (DOC08-OD-02).

## 10. Impact on locked screens
- **S-RX-01:** unchanged.
- **S-RX-02:** unchanged, except the page thumbnails for a file later confirmed as DOC-08 are cleared from the device after saving (PROPOSED).
- **S-RX-03:** v1.7 restricted review in view 3C (DOC08-OD-01): a short notice "This is a genetic report. It will be kept restricted." · **Report details** (name, date, lab, test name) · **Confirm Details** · no findings section · **Save Restricted Record**. The 3B type hint never names a gene or result.
- **S-RX-04:** not used.
- **After save:** one confirmation sheet explaining restriction (where it’s hidden, unlock needed, excluded from sharing) with **Done**; then S-RX-05.
- **S-RX-05:** line "Restricted record saved · details verified"; no test name.
